Configuration du Switch Cisco

Présentation générale

Le switch Cisco (Catalyst 2960X) est le point central de connexion pour tous les appareils du réseau filaire. Il remplit trois rôles essentiels :

  • Segmentation réseau : Création et gestion de 5 VLANs pour isoler les utilisateurs par rôle
  • Interconnexion : Liaison avec le routeur via un port trunk pour la communication inter-VLAN
  • Sécurité DHCP : Protection contre les serveurs DHCP malveillants (DHCP Snooping)

Architecture physique

Le switch dispose de 24 ports GigabitEthernet :

  • Ports 1-4 : VLAN 10 (Employés) — 4 ports
  • Ports 5-9 : VLAN 20 (Direction) — 5 ports
  • Ports 10-14 : VLAN 30 (Admin IT) — 5 ports
  • Ports 15-19 : VLAN 40 (DMZ / Serveurs) — 5 ports
  • Ports 20-21 : VLAN 60 (WiFi / Points d'accès) — 2 ports
  • Port 24 : Trunk vers le routeur — 1 port
  • Ports 22-23 : Libres

Configuration étape par étape

Étape 1 : Création des VLANs

Les VLANs (Virtual LANs) sont des domaines de broadcast logiques. Chaque VLAN est isolé et ne peut communiquer avec les autres que via le routeur :

enable
configure terminal
vlan 10
 name Employes
vlan 20
 name Direction
vlan 30
 name Admin
vlan 40
 name DMZ
vlan 60
 name Wi-Fi
exit

Explication : Cette configuration crée 5 VLANs identifiés par un numéro (10, 20, etc.) et un nom descriptif. Les numéros doivent correspondre aux configurations du routeur pour que le routage fonctionne correctement.

Étape 2 : Affectation des ports utilisateurs

Chaque port utilisateur est configuré en mode access et assigné à un VLAN. Les utilisateurs connectés à ces ports reçoivent une adresse IP du VLAN correspondant :

Ports VLAN 10 (Employés)

interface range GigabitEthernet1/0/1 - 4
 switchport mode access
 switchport access vlan 10
exit

Ports VLAN 20 (Direction)

interface range GigabitEthernet1/0/5 - 9
 switchport mode access
 switchport access vlan 20
exit

Ports VLAN 30 (Admin)

interface range GigabitEthernet1/0/10 - 14
 switchport mode access
 switchport access vlan 30
exit

Ports VLAN 40 (DMZ)

interface range GigabitEthernet1/0/15 - 19
 switchport mode access
 switchport access vlan 40
exit

Ports VLAN 60 (WiFi)

interface range GigabitEthernet1/0/20 - 21
 switchport mode access
 switchport access vlan 60
exit

Explication : La commande switchport mode access place le port en mode accès (non-trunk). Un utilisateur connecté à un port en mode accès reçoit immédiatement un tag VLAN. L'utilisation de interface range permet de configurer plusieurs ports en une seule commande.

Exemple : Si vous branchez un PC sur le port 1, le switch ajoute automatiquement le tag VLAN 10 à tous les paquets provenant de ce port.

Étape 3 : Configuration du trunk vers le routeur

Le trunk est un port spécial qui transporte le trafic de tous les VLANs simultanément. C'est la liaison qui permet au routeur de voir tous les VLANs :

interface GigabitEthernet1/0/24
 description Trunk_vers_Routeur
 switchport mode trunk
exit

Explication : Contrairement aux ports access, le port trunk transporte des trames étiquetées (tagged). Chaque trame inclut le numéro VLAN dans son en-tête (8021.Q). Le routeur reçoit ces trames avec leur tag VLAN et peut les traiter via les sous-interfaces correspondantes.

Différence clé :

  • Port Access : Un seul VLAN, pas de tag (mode natif)
  • Port Trunk : Tous les VLANs, chaque trame a son tag VLAN

Sauvegarde de la configuration

end
write memory

Explication : La commande write memory (ou copy running-config startup-config) sauvegarde la configuration en NVRAM du switch. Sans cette commande, la configuration serait perdue au redémarrage.

Sécurité : DHCP Snooping

Qu'est-ce que le DHCP Snooping ?

Le DHCP Snooping est une protection contre les serveurs DHCP malveillants (rogue DHCP servers). Un attaquant pourrait brancher son propre serveur DHCP et distribuer de fausses adresses IP pour intercepter le trafic. Le DHCP Snooping crée une liste blanche de serveurs DHCP autorisés :

Étape 4 : Activation globale du DHCP Snooping

enable
configure terminal
ip dhcp snooping
ip dhcp snooping vlan 10,20,30,40,60
no ip dhcp snooping information option
exit

Explication détaillée :

  • ip dhcp snooping : Active globalement la fonction
  • ip dhcp snooping vlan 10,20,30,40,60 : Active le snooping pour ces VLANs spécifiques
  • no ip dhcp snooping information option : Désactive l'ajout automatique de l'option 82 aux paquets DHCP. Certains routeurs/serveurs la rejettent, ce qui bloquerait les clients DHCP

Étape 5 : Configuration des ports de confiance (Trusted)

Les ports de confiance sont autorisés à recevoir des réponses DHCP. Seul le vrai serveur DHCP et le port trunk doivent être de confiance :

enable
configure terminal
! Serveur DHCP légitime en DMZ (port 15)
interface GigabitEthernet1/0/15
 description Serveur_DHCP_Legitime
 ip dhcp snooping trust
exit
! Port Trunk vers le routeur
interface GigabitEthernet1/0/24
 description Trunk_vers_Routeur
 ip dhcp snooping trust
exit

Explication :

  • Port 15 (Serveur DHCP) : En tant que ports de confiance, il peut envoyer des réponses DHCP (DHCP ACK)
  • Port 24 (Trunk) : De confiance car c'est la liaison vers le routeur qui relaye les requêtes DHCP
  • Tous les autres ports : Sont non-trusted par défaut. Ils peuvent envoyer des requêtes DHCP mais pas des réponses

Comment fonctionne le DHCP Snooping ?

Voici le flux de communication DHCP avec le snooping actif :

  1. Un client DHCP (PC en VLAN 10) envoie une requête DHCP (DISCOVER)
  2. Le switch reçoit la requête sur le port 1 (non-trusted)
  3. Comme le port est non-trusted, le switch laisse passer (il doit bien y avoir des requêtes !)
  4. La requête arrive au routeur (port 24 = trusted)
  5. Le routeur la relaye au serveur DHCP en DMZ
  6. Le serveur DHCP répond (DHCP OFFER) au routeur
  7. Le routeur envoie la réponse vers le port 24 du switch (trusted)
  8. Le switch la relaie au port 1
  9. Le client reçoit l'adresse IP

Cas d'attaque bloquée : Si un attaquant branche un serveur DHCP malveillant sur le port 2 (non-trusted), ses réponses DHCP seront bloquées par le switch et n'atteindront jamais les clients.

Étape 6 : Configuration du rate limit DHCP

Même avec DHCP Snooping, un attaquant peut envoyer massivement des requêtes DHCP pour surcharger le serveur (attaque par déni de service). Le rate limit limite le nombre de requêtes DHCP par port :

enable
configure terminal
! Ports VLAN 10 (Employés)
interface range GigabitEthernet1/0/1 - 4
 ip dhcp snooping limit rate 10
exit
! Ports VLAN 20 (Direction)
interface range GigabitEthernet1/0/5 - 9
 ip dhcp snooping limit rate 10
exit
! Ports VLAN 30 (Admin)
interface range GigabitEthernet1/0/10 - 14
 ip dhcp snooping limit rate 10
exit
! Ports VLAN 40 (DMZ, sauf port 15)
interface range GigabitEthernet1/0/16 - 19
 ip dhcp snooping limit rate 10
exit
! Ports VLAN 60 (WiFi - Points d'accès)
interface range GigabitEthernet1/0/20 - 21
 ip dhcp snooping limit rate 30
exit

Explication :

  • limit rate 10 : Maximum 10 requêtes DHCP par seconde
  • limit rate 30 : Sur les ports WiFi (20-21), la limite est plus élevée (30/sec) car de nombreux utilisateurs transitent par un seul port via les points d'accès
  • Si un port dépasse la limite, le switch le désactive automatiquement (errdisable) pour protéger le serveur DHCP

Étape 7 : Récupération automatique après errdisable

Quand un port est désactivé, il doit être réactivé manuellement ou automatiquement. Cette configuration active la récupération automatique :

configure terminal
errdisable recovery cause dhcp-rate-limit
errdisable recovery interval 300
exit

Explication :

  • errdisable recovery cause dhcp-rate-limit : Autorise la récupération automatique des ports errdisable causés par un dépassement du rate limit DHCP
  • errdisable recovery interval 300 : Après 300 secondes (5 minutes), le switch réactive automatiquement le port
  • Sans cette configuration : Le port resterait désactivé jusqu'à une intervention manuelle (no shutdown)

Concepts clés

VLAN (Virtual Local Area Network)

Un VLAN est un domaine de broadcast logique. Les VLANs offrent :

  • Isolement : Les machines d'un VLAN ne voient que le trafic broadcast de leur VLAN
  • Sécurité : Empêche un utilisateur du VLAN 10 d'accéder directement aux serveurs du VLAN 40
  • Flexibilité : Un VLAN peut s'étendre sur plusieurs switchs

Tagging VLAN (802.1Q)

Le tagging VLAN ajoute un en-tête spécial aux trames Ethernet :

  • Trame non-tagged (mode access) : L'utilisateur envoie une trame normale, le switch ajoute le tag VLAN
  • Trame tagged (mode trunk) : La trame inclut déjà le numéro VLAN dans son en-tête

Problèmes courants et solutions

Problème 1 — Les utilisateurs ne peuvent pas communiquer entre VLANs

Cause : C'est le comportement attendu ! Les VLANs sont isolés par défaut. Pour que deux VLANs se parlent, ils doivent passer par le routeur.

Vérification : Un utilisateur du VLAN 10 peut pinger le routeur (192.168.136.1) mais pas un utilisateur du VLAN 20 directement. Il faut passer par le routeur.

Problème 2 — Le routeur ne voit pas tous les VLANs

Cause : Le port trunk n'est pas correctement configuré ou le routeur n'a pas les sous-interfaces correspondantes.

Solution : Vérifier que le port 24 du switch est en switchport mode trunk. Vérifier sur le routeur que les sous-interfaces GigaEth0/0/1.10, .20, .30, .40, .60 existent avec la commande show ip interface brief.

Problème 3 — Les clients DHCP ne reçoivent pas d'adresse IP

Cause : DHCP Snooping bloque les réponses du serveur, ou le port du serveur n'est pas de confiance.

Solution : Vérifier que le port 15 (serveur DHCP) a la commande ip dhcp snooping trust. Vérifier avec show ip dhcp snooping binding que le switch voit les liaisons DHCP.

Problème 4 — Un port se désactive soudainement (erreur errdisable)

Cause : Le port a dépassé la limite DHCP rate limit ou une autre condition d'erreur a été détectée.

Vérification : Utiliser show interface status err-disabled pour voir les ports désactivés. Attendre 5 minutes (300 secondes) pour la réactivation automatique, ou réactiver manuellement avec no shutdown.

Problème 5 — Un serveur DHCP malveillant distribue des adresses

Cause : DHCP Snooping n'est pas activé ou le port du serveur malveillant est marqué comme trusted.

Solution : Vérifier que seuls les ports 15 (serveur légitime) et 24 (trunk) ont ip dhcp snooping trust. Les autres ports sont non-trusted par défaut et bloqueront les réponses DHCP.
